The fastest way to answer **"Can this project use SolarAPP+?"** is to separate two questions:

1. Is the **project type** within SolarAPP+'s current technical scope?
2. Does the **specific jurisdiction** accept SolarAPP+ for that feature at that address?

A project can satisfy the platform's general scope and still need a different local submission path if the jurisdiction has not enabled the applicable SolarAPP+ feature.

## Battery storage

SolarAPP+ supports qualifying **residential PV + storage** projects. Its current eligibility guidance lists a **20 kWh limit for an individual battery** and up to **80 kWh aggregate ESS capacity depending on installation location**, along with other configuration requirements. See [SolarAPP+: What types of systems are eligible?](https://help.gosolarapp.org/article/43-what-types-of-systems-are-eligible-for-solarapp-review).

Do not stop at "SolarAPP+ supports batteries." Check the actual battery/inverter configuration against the current eligibility checklist and confirm that the jurisdiction supports the relevant PV+ST or storage feature.

SolarAPP+'s 6.15 software release also states that the **ESS permit fee was updated to $30**. That is a SolarAPP+ platform fee update; it does **not** mean the total city/county permit cost is $30, because local AHJ fees can still apply separately. See [SolarAPP+ Software Releases](https://help.gosolarapp.org/article/180-software-releases).

## Main panel upgrade (MPU)

SolarAPP+ has platform support for main panel upgrades, but **local availability varies by jurisdiction**. SolarAPP+'s live availability table distinguishes PV, PV+ST, storage and MPU features. See [Where is SolarAPP+ available?](https://www.gosolarapp.org/where-is-solarapp-available).

Therefore, an MPU does not automatically make every project ineligible, and it also does not mean every participating jurisdiction will process the MPU inside the SolarAPP+ path.

## Existing PV

SolarAPP+ currently supports certain new PV or PV+storage projects at sites with an **existing PV-only system**. Its existing-systems guidance states, among other conditions, that:

- the existing system's equipment must be on the CEC current or archived equipment lists;
- the existing system must not already include storage;
- the new system must include new solar modules and an inverter; and
- modification of the existing solar system is not permitted within that workflow.

See [Existing Systems in SolarAPP+](https://help.gosolarapp.org/article/388-solarapp-and-existing-systems).

That means "there is already solar on the house" is no longer an automatic no — but the exact existing-system facts matter.

## Ground-mounted solar

**Ground-mounted solar is currently outside SolarAPP+'s scope.** SolarAPP+'s August 2026 eligibility guidance lists ground-mounted solar among systems that must use the jurisdiction's traditional permitting process. See [SolarAPP+ eligibility](https://help.gosolarapp.org/article/43-what-types-of-systems-are-eligible-for-solarapp-review).

## Homeowner / DIY installation

This changed in 2026 and needs a more precise answer than a blanket yes/no.

SolarAPP+'s **6.15 release (June 30, 2026)** says homeowners can now register and create projects in SolarAPP+, but **full permit submission is currently available only in DORA-eligible jurisdictions**. At the same time, SolarAPP+'s general eligibility guidance still lists systems installed by homeowners as outside the ordinary SolarAPP+ scope. See [SolarAPP+ Software Releases](https://help.gosolarapp.org/article/180-software-releases) and the current [eligibility guidance](https://help.gosolarapp.org/article/43-what-types-of-systems-are-eligible-for-solarapp-review).

So the practical decision is:

- **Colorado / DORA-eligible location:** check the current DORA + SolarAPP+ homeowner submission path for the address.
- **Other jurisdictions:** do not assume homeowner registration means homeowner permit submission is enabled. Check the jurisdiction feature and licensing rules; the traditional AHJ permit path may still be required.

SolarAPP+'s DORA guide also makes clear that a DORA electrical permit remains a separate required milestone in covered territory, even when SolarAPP+ performs the automated plan review. See [SolarAPP+ with DORA](https://help.gosolarapp.org/article/440-solarapp-with-dora-installer-guide).

## Quick decision table

| Project fact | SolarAPP+ implication |
| --- | --- |
| Residential rooftop PV | Potentially eligible; check full criteria + jurisdiction |
| PV + battery | Potentially eligible; check storage criteria + jurisdiction feature |
| MPU | Platform-supported, but jurisdiction availability varies |
| Existing PV-only system | Potentially eligible under the current existing-system conditions |
| Existing system already has storage | Not within the cited existing-PV workflow |
| Ground mount | Outside current SolarAPP+ scope |
| Homeowner-installed system | Registration/project creation is now available; full submission is currently limited to DORA-eligible jurisdictions, otherwise check local/traditional path |
| Commercial / utility-scale | Outside current SolarAPP+ scope |

## What GridPermit should ask before answering "SolarAPP+ or traditional permit?"

- jurisdiction/AHJ;
- project address or at least city;
- rooftop vs ground mount;
- new PV only, PV+storage, or storage addition;
- existing PV or existing storage;
- MPU/main-breaker work;
- contractor vs homeowner installation;
- service and equipment configuration where relevant to the current eligibility checklist.

Only after those facts are known can the answer be reduced to a reliable permit path.

## California examples: automated review is local

An automated path can differ from one city to the next. [Ontario uses Symbium for eligible residential rooftop solar](/california/ontario/solar-permit-guide/), while [Lakewood documents a SolarAPP+ path](/california/lakewood/solar-permit-guide/) and [Cypress has its own local permit requirements](/california/cypress/solar-permit-guide/). Check the city guide before treating platform eligibility as local permit eligibility.
