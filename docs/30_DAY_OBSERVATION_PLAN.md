# 30-Day Observation Plan

Written 2026-08-15, at the end of the Launch & Organic Growth technical audit. GridPermit is now technically search-ready (see the companion report); the open question is what actually happens once Google has time to crawl, index, and rank it. This plan lists only metrics that can change a real decision — not a dashboard of everything measurable.

**Prerequisite note:** as of this writing, neither Google Search Console API access nor GA4 API access exists in this repository/session. Every metric below needs one of those two connected before it can be observed at all. Setting up that access (a one-time, low-risk step — verifying the existing `google-site-verification` meta tag's property in GSC, and a GA4 API credential) is itself the first action, not something to defer for 30 days.

| Metric | Source | What it tells us | What would cause action | What action would follow |
|---|---|---|---|---|
| **Indexed page count** | GSC Coverage report | Whether Google has actually crawled and indexed the site beyond the single stale result found this session | Indexed count stays near-zero after 2+ weeks, or a large share of pages show "Discovered, not indexed" | Investigate crawl budget, check for a `robots.txt`/server issue that wasn't visible from the repo, consider manual URL inspection/reindex requests for Tier-1 pages only |
| **Total impressions (7-day and 28-day)** | GSC Performance report | Whether GridPermit pages are being *shown* in search results at all, independent of clicks | Impressions stay at literal zero after indexing is confirmed | Check whether titles/descriptions are actually the ones being served (cache lag), check query relevance |
| **Total clicks** | GSC Performance report | Whether real users are reaching the site from organic search | Impressions exist but clicks stay near-zero for 2+ weeks | Review CTR by page — see the low-CTR row below — before touching anything else |
| **Top landing pages (by clicks)** | GSC Performance report | Which page family is actually earning traffic — homepage, `/permits`, a specific state hub, or specific locality guides | One page family dominates entirely, or Tier-1 pages get zero traffic while a low-priority page gets disproportionate traffic | Re-examine internal linking / title relevance for the underperforming Tier-1 pages |
| **Top queries** | GSC Performance report | What real people are actually typing to find GridPermit — validates or invalidates the query-intent assumptions in `docs/SERP_RESEARCH.md` | A query pattern appears repeatedly that GridPermit's data could answer but no page currently targets | Check whether an *existing* locality/state page already answers it but under-surfaces the answer — improve that page's on-page structure, don't build a new page speculatively |
| **Pages with impressions but zero clicks** | GSC Performance report | Pages that are being shown but not chosen — a title/description problem, not a content problem | A Tier-1 page (state hub, high-completeness locality guide) shows meaningful impressions (not single-digit noise) with a CTR far below the site average | Rewrite that specific page's title/description only — not a template-wide rewrite unless the pattern repeats across many pages |
| **`search_used` event count** | GA4 | Whether visitors use the on-site search, and how often it returns nothing | A meaningful share of searches return zero results | Pull the actual zero-result query strings (already logged) and check whether GridPermit's dataset has a real answer that isn't surfaced — do not build new pages speculatively without checking existing data first |
| **`permit_guide_clicked` event count** | GA4 | Whether the national discovery flow (`/permits` → state → locality) is actually being used, not just linked | Near-zero clicks despite `/permits` receiving traffic | Review `/permits` page layout/copy for a genuine usability defect — not a coverage defect |
| **`official_source_clicked` event count** | GA4 | Whether readers trust the guides enough to follow through to the primary source — a genuine trust-signal metric, not vanity | Sustained near-zero rate relative to guide views | Review whether source links are visually prominent enough on the page — a real UX check, not a data problem |
| **`external_partner_clicked` (installer CTA) event count** | GA4 | The top of the monetization funnel — see `docs/MONETIZATION_STRATEGY.md` Section 9's "next experiment" | 2-4 weeks of real traffic accumulate with a click rate meaningfully different from the 2-5% assumption range | Feed the real rate back into the unit-economics model in `docs/MONETIZATION_STRATEGY.md`; do not change CTA placement based on fewer than the traffic volume that assumption range implies |
| **`pro_interest_clicked` event count** | GA4 | Real willingness-to-pay signal for the GridPermit Pro hypothesis — explicitly not being built now | A meaningful, sustained click volume accumulates | Revisit whether GridPermit Pro moves from a validation page to a real scoping conversation — still not a decision to build tonight or in the next 30 days |
| **`page_not_found` event count** | GA4 | Whether real visitors are hitting broken/removed links, internally or from external referrers | A specific URL pattern repeats meaningfully in 404 events | Check whether it's an internal linking defect (fixable here) or an external link into a URL that no longer exists (may need a redirect) |

## Explicit non-goals for this 30-day window

- **Do not treat GSC/GA4 numbers being small or zero as a defect** in week 1–2. A brand-new, previously-uncrawled site has no traffic history to compare against — see `docs/SEARCH_BASELINE.md` note (N/A this session, no GSC access) and the explicit instruction not to interpret early "0" as failure.
- **Do not set numeric thresholds where no baseline yet exists.** Every "what would cause action" trigger above is qualitative (a real pattern, a meaningful share, a repeat) rather than an invented number like "if clicks < 50" — GridPermit has no prior traffic to calibrate a number against yet. Once 30 real days of data exist, this document should be revised with actual thresholds.
- **Do not expand coverage, build new pages, or add new verticals based on early query data alone.** A repeated query pattern is a signal to check whether existing data already answers it (Phase 26 of the launch mission), not a mandate to build.
